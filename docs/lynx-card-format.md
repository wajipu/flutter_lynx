## 1. 定位与选型

`lynx-card/1` 是一份**自包含、声明式的 JSON 组件树 DSL**，供大模型（小柯助手）现场生成、由桌面 Flutter runtime 直接解析渲染。典型消费方：

1. **确认卡**：候选字段展示 + 确认/取消按钮，点击经 `ui.confirmResult` Bridge 回传宿主；
2. **展示型数据卡片/图表**：只读渲染注入数据。

**为什么是 JSON 组件树，而不是受限 JS 子集**（选型结论）：

| 维度           | JSON 组件树 DSL（选定）                                    | 受限 JS 子集                                                                           |
| -------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 模型生成可靠率 | LLM 输出 JSON 的可靠率极高，语法完全确定，一次生成即合法   | 要求模型在无执行验证条件下严守"无循环/无闭包/仅白名单 API"约束，越界率高且难以静态拦截 |
| 安全           | 无执行语义，天然无注入面；解析器只是树遍历 + 白名单校验    | 需要解释器/沙箱，任何疏漏都是任意代码执行                                              |
| 可校验性       | 深度/节点数/未知节点在解析期确定性拒绝或降级               | 需 AST 级审查，覆盖不全                                                                |
| 跨端语义       | 明确定位"桌面纯 Flutter 渲染"，不与真引擎竞争语义          | 移动 tasm 引擎执行完整 JS，桌面自研解释器必然与真引擎行为分叉                          |
| 表达力         | `{{path}}` 绑定 + `when`/`list` 覆盖确认卡与数据卡全部需求 | 图灵完备但场景不需要                                                                   |

## 2. 总体结构（envelope）

模板即一段 UTF-8 JSON 文本：

```json
{
  "format": "lynx-card/1",
  "state": { "quantity": 25 },
  "body": { "type": "container", "children": [] }
}
```

| 字段     | 类型   | 必填 | 说明                                                                                   |
| -------- | ------ | ---- | -------------------------------------------------------------------------------------- |
| `format` | string | 是   | 必须精确等于 `"lynx-card/1"`；其他值整体拒绝                                           |
| `state`  | object | 否   | 卡片本地初始 state，仅模板内部可读写（输入项写入、按钮携带），宿主数据进不来也覆盖不了 |
| `body`   | node   | 是   | 根节点，必须且只能一个                                                                 |

解析器**宽容剥离首尾 Markdown 代码栅栏**（` ```json … ``` `），栅栏内必须仍是纯 JSON。

## 3. 数据与绑定

### 3.1 作用域

渲染时存在两层只读数据 + 一层可变 state：

| 层    | 来源                                                   | 引用方式                                      |
| ----- | ------------------------------------------------------ | --------------------------------------------- |
| data  | `initialData`（宿主注入），`updateData` 运行时合并覆盖 | 直接写路径，如 `{{goods.name}}`               |
| state | envelope `state` 初始化；`input` 组件写入              | 必须带 `state.` 前缀，如 `{{state.quantity}}` |

data 与 state 命名空间隔离：宿主注入名为 `state` 的顶层 key 无法渗透进卡片 state（state 只能经 `state.` 前缀访问），反之亦然。

### 3.2 绑定语法 `{{path}}`

- **整串精确绑定**：字符串值整体恰为一个 `{{path}}` 时，解析为该路径的**原类型值**（number/bool/array/object 均保留）。如 `"items": "{{alertList}}"` 直接拿到数组。
- **内嵌插值**：字符串中含一个或多个 `{{path}}` 时做字符串插值，缺失路径插为空串。如 `"当前库存 {{stock.count}}，阈值 {{stock.threshold}}"`。
- **路径语法**：以 `.` 分段；数组用数字下标分段（`items.0.name`）。缺失路径求值为 null，不报错。
- **深度绑定**：对象/数组内部所有字符串值同样参与绑定（按钮 `params` 即靠此注入运行时字段值）。
- **标量转字符串**：整数保持整型书写（`25`）；浮点数为整数值时省略小数尾零（`25.0` → `25`）；bool 转 `true/false`；null 转空串。

## 4. 节点与组件

每个节点是对象：`{ "type": "<组件名>", ...属性 }`。除注明必填的属性外均可省略，类型不符的属性一律回退默认值（不拒绝整个卡片）。

**所有节点通用属性**：

| 属性   | 类型                 | 说明                                                                                  |
| ------ | -------------------- | ------------------------------------------------------------------------------------- |
| `when` | string（绑定表达式） | 假值隐藏节点。真值判定：`null`、`false`、`0`、`""` 为假，其余（含空数组、空对象）为真 |
| `flex` | number ≥ 0           | 在 `row`/`column` 父容器中按权重伸展（对应 Flexbox `flex-grow`）                      |

### 4.1 `container` — 布局容器

| 属性               | 默认        | 说明                                                                                 |
| ------------------ | ----------- | ------------------------------------------------------------------------------------ |
| `direction`        | `"column"`  | `"column"` 纵向 / `"row"` 横向                                                       |
| `children`         | `[]`        | 子节点数组                                                                           |
| `gap`              | `0`         | 子节点间距（逻辑像素）                                                               |
| `padding`          | `0`         | 四边内边距（逻辑像素）                                                               |
| `background`       | 无          | 背景色                                                                               |
| `radius`           | `0`         | 圆角                                                                                 |
| `border`           | 无          | 1px 边框色                                                                           |
| `width` / `height` | 自适应      | 固定尺寸（逻辑像素）                                                                 |
| `align`            | `"stretch"` | 交叉轴对齐：`start` / `center` / `end` / `stretch`（CSS block 习惯：默认撑满交叉轴） |

### 4.2 `text` — 文本

`text`（必填，绑定后必须是字符串）、`size`（默认 14）、`color`（默认主题主文字色）、`weight`（`"normal"` / `"medium"` / `"bold"` 或 100–900 数字）、`align`（`start`/`center`/`end`，默认 `start`）、`maxLines`（超出行数省略号截断）。

### 4.3 `field` — 键值行（候选字段展示推荐用）

`label`（左列固定宽 96，次级色）、`value`（右侧自动伸展，支持绑定；非字符串标量自动转字符串）。

### 4.4 `input` — 输入框（写入卡片 state）

| 属性          | 说明                                                         |
| ------------- | ------------------------------------------------------------ |
| `bind`        | 必填。写入的 state 键名（实际存储于 `state.<bind>`）         |
| `value`       | 可选绑定。`state.<bind>` 为 null 时的初值来源（如 `"{{quantity}}"` 从宿主数据预填候选值；用户一旦输入即以 state 为准） |
| `label`       | 可选，输入框上方说明文字                                     |
| `placeholder` | 占位提示                                                     |
| `keyboard`    | `"text"`（默认）/ `"number"`（数字键盘，值为 `null` 或数字） |

初值取 `state.<bind>`；为 null 时回退 `value` 绑定初值（确认卡场景：宿主把候选值经 initialData 注入，模板用 `value: "{{quantity}}"` 预填）。用户输入即写回 state，供 `{{state.<bind>}}` 绑定与按钮 `withState` 携带。

### 4.5 `button` — 按钮（动作出口）

| 属性       | 默认        | 说明                                                                     |
| ---------- | ----------- | ------------------------------------------------------------------------ |
| `text`     | 必填        | 按钮文案                                                                 |
| `style`    | `"primary"` | `primary`（主色底白字）/ `secondary`（浅灰底深字）/ `danger`（红底白字） |
| `once`     | `true`      | 点击发起动作后禁用（防连点重复回传）；`false` 允许重复点击（如刷新）     |
| `action`   | 必填        | 动作对象，见下                                                           |
| `disabled` | `false`     | 支持 `{{}}` 绑定                                                         |

**action 对象**：

```json
{
  "bridge": "ui.confirmResult",
  "params": { "action": "confirm", "confirmationId": "{{confirmationId}}" },
  "withState": "finalFields",
  "applyResultTo": "refreshResult"
}
```

| 字段            | 说明                                                                                            |
| --------------- | ----------------------------------------------------------------------------------------------- |
| `bridge`        | 必填。`"<module>.<method>"`，必须在白名单内（见 §6）；白名单外解析期即按禁用渲染并记日志        |
| `params`        | 静态参数对象，所有字符串值深度绑定，可包含任意 JSON 结构                                        |
| `withState`     | 可选。给出键名 K 时，点击时把卡片 state 整体作为 `params[K]` 附带（state 为空对象则不附带）     |
| `applyResultTo` | 可选。把 Bridge 响应的 `data`（须为对象）合并进 data 作用域的该键下并触发重渲染（只读刷新场景） |

无 `action` 的 button 按禁用渲染。

### 4.6 `list` — 列表循环

| 属性    | 默认     | 说明                                                                       |
| ------- | -------- | -------------------------------------------------------------------------- |
| `items` | 必填     | 绑定或内联数组；每项可为任意值                                             |
| `as`    | `"item"` | 循环内通过 `{{item}}`（整项）与 `{{item.x}}`（字段）访问；下标 `{{index}}` |
| `body`  | 必填     | 单节点模板，逐项渲染                                                       |
| `empty` | 无       | items 为 null/空数组时渲染的替身节点                                       |
| `gap`   | `8`      | 项间距                                                                     |

items 超过 **100** 条截断（防抖）；非数组按空处理。

### 4.7 `chart` — 图表（只读）

`variant: "bar"`（当前唯一）：水平条形图。`items` 必填，形如 `[{"label": "周一", "value": 18200}, …]`（value 为 number，非数值项跳过），条长按最大值归一；`color` 可选（默认主题主色）。

### 4.8 `divider` / `spacer`

- `divider`：分隔线，`color` 可选。
- `spacer`：空白占位，`size`（默认 8）。

| ----------------- | --------- | --------- |
| 卡片背景          | `#FFFFFF` | `#1E1F22` |
| 主文字            | `#1F2329` | `#E8EAED` |
| 次级文字          | `#646A73` | `#A8ADB4` |

## 6. 安全边界

1. **无执行语义**：模板不含任何代码；解析器只做 JSON 解析、树遍历与白名单校验。
2. **无网络、无文件**：渲染过程不发起任何网络请求、不读宿主文件系统；模板没有图片组件。
3. **Bridge 白名单**（模板动作唯一出口，精确匹配 `module.method`）：
   - `ui.confirmResult`（确认卡回传）
   - `ui.showToast`
   - `system.getSystemInfo`、`system.getNetworkType`（只读）
   - `data.messageUnreadTotal`、`data.inventoryAlertList`、`data.paymentStatsOverview`（只读白名单，须经宿主代调 delegate 开通）
   - 白名单外动作解析期按禁用渲染并记日志，绝不放行；`storage`/`router` 等写态/导航模块一律不在白名单。
4. **state 隔离**：宿主数据只能进 data 层；卡片 state 只被模板内输入与初始 envelope 影响。
5. **ID 一律字符串**：`confirmationId` 等标识字段必须以字符串注入与回传（JSON 大整数经 JS/桥层会丢精度）；模板不得做数值转换。

## 7. 限制与拒绝/降级行为

**整体拒绝**（触发 `onLoadFail`，宿主拿到明确错误）：

| 条件                                                                      | 阈值      |
| ------------------------------------------------------------------------- | --------- |
| 源文本（UTF-8）超长                                                       | > 256 KiB |
| JSON 括号嵌套深度（预扫描，含字符串内，保守）                             | > 32      |
| 非法 JSON / 顶层非对象 / `format` ≠ `"lynx-card/1"` / `body` 缺失或非节点 | —         |
| 解析后节点总数                                                            | > 512     |

**单点降级**（不失败，渲染可用的替身）：

| 情形                                      | 行为                                              |
| ----------------------------------------- | ------------------------------------------------- |
| 未知 `type`                               | 渲染灰色占位文本「不支持组件 x」，children 不展开 |
| `children` 非数组                         | 忽略 children                                     |
| 属性类型不符                              | 回退该属性默认值                                  |
| `list.items` 非数组 / 缺失                | 按 `empty` 节点或空处理                           |
| 动作 bridge 不在白名单 / button 无 action | 按钮按禁用渲染 + 日志                             |

## 8. 平台策略

| 平台                        | `loadFromSource(lynx-card 文本)` | 说明                                                                                                                                                                                        |
| --------------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 桌面（macOS/Windows/Linux） | ✅ 本文规范完整渲染              | 纯 Flutter 实现，不依赖原生引擎                                                                                                                                                             |
| 移动（Android/iOS）         | ❌ 明确报错                      | Dart 侧检测到 lynx-card 信封直接抛出带指引的 `ArgumentError`（走 `onLoadFail`），绝不静默喂给真引擎；移动端模板继续走 rspeedy/tasm **编译产物**（`loadFromTemplateBytes` / `url` 文件链路） |

移动端真引擎（Lynx 4.1 tasm）执行的是编译字节码，无法执行本文 DSL；两条链路定位不同：**模型现场生成 → 桌面 lynx-card；随版本内置的正式小程序 → tasm 编译产物**。若未来移动端需要 lynx-card，应由原生各自实现同规范渲染器（规范即契约），而不是把 JSON 伪装成引擎输入。

## 10. 与官方 Generative UI（A2UI/OpenUI）路径的评估（决策记录）

官方 Lynx 提供两条"AI 运行时生成 UI"正式路径（ReactLynx 侧）：

- **A2UI**：Google 发起的 Agent-to-UI 开放协议。Agent 输出受 Schema 约束的声明式 UI
  消息流，按预授权 Catalog 渲染；Lynx 官方实现 `@lynx-js/genui/a2ui` 是 ReactLynx 组件，
  支持流式渐进生成与 Agent/Client 两类 Action。
- **OpenUI**：渲染紧凑流式 OpenUI Lang 为原生界面，带响应式状态、工具调用与可扩展组件库。

**本任务决策：自研 lynx-card/1，不直接采用官方路径**，理由：

1. **运行时不匹配**：官方两条路径的渲染实现都是 ReactLynx 组件，必须跑在 Lynx 真引擎内。
   本格式的消费端是宿主 App **桌面 Flutter runtime（纯 Flutter，无引擎、无 ReactLynx）**——
   采纳官方路径并不能"白送"渲染器，仍需在 Flutter 侧实现一个协议级渲染器
   （消息 Schema 校验、Catalog、消息队列、Action 路由），复杂度数倍于场景所需，
   且需持续跟随协议版本演进。
2. **场景不匹配**：确认卡/数据卡是**一次性完整输出**（非流式），动作直回宿主
   （`ui.confirmResult` → 宿主路由 execute/cancel，不经 Agent 回路），组件面固定 9 个。
   A2UI/OpenUI 的核心增益（流式渐进生成、Agent 行动回路、Catalog 生态、多轮 UI 更新）
   在本场景全部用不上。
3. **设计哲学一致**：A2UI "Catalog 预授权、不让模型自由生成代码、安全边界业务控制"
   的哲学与 lynx-card/1 完全同向——后者等价于一个 9 组件迷你 Catalog + 单一动作出口白名单。

**切换到官方路径的约定（演进）**：若移动端未来需要运行时 Generative UI（真引擎侧），
正解是在 `lynx_miniapp_template` 建 A2UI/OpenUI 宿主 bundle，届时桌面渲染器应对齐
A2UI 协议子集或整体替换为官方协议渲染；若场景扩展到流式/多轮 agentic UI，应重新评估。

## 9. 版本策略

- `format` 精确匹配 `lynx-card/1`；不认识的 format 一律拒绝（模型提示语中要求输出该版本）。
- 未来不兼容变更升主版本号（`lynx-card/2`），旧 runtime 拒绝新版本而不是误读。
